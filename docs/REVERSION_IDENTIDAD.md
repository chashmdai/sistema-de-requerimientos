# Reversión no destructiva de identidad
1. Conservar V11, cuentas, asignaciones/revocaciones, perfiles históricos, eventos, coberturas y origen. No ejecutar DOWN, DELETE de evidencia, Flyway repair/clean, reset de Git ni recreaciones de esquema/volumen.
2. Detener exclusivamente el laboratorio institucional con scripts/Institucional-Completo-Linux.py <privado> --detener. No detener MySQL, workers, PISEE ni aplicaciones públicas.
3. Para cerrar temporalmente nuevos accesos, conservar el artefacto nuevo, configurar institucional.identidad.habilitada=false e institucional.identidad.legado-pruebas=false y reiniciar. El login queda cerrado; las sesiones no deben considerarse trasladables. Es una retirada de acceso, no una conversión de cuentas.
4. No volver a habilitar el acceso compartido para recuperar una función. Restaurar un JAR anterior que ignora los flags de identidad podría reactivar ese mecanismo: si se necesita analizarlo, usar institucional.nucleo.habilitado=false y mantener cerradas las rutas, sin intervenir la custodia.
5. El respaldo privado application.antes-identidad.properties contiene secretos anteriores: no copiarlo a Git ni restaurarlo ciegamente. runtime-antes-identidad.jar se conserva privado para revisión; el activo está separado de target.
6. Para reactivar, restaurar los flags individuales, comprobar HTTPS/CSRF/estado de cuenta TI, validar Flyway con migrador separado y usar el mismo esquema/almacén. El archivo inicial se marca .aplicado; el reinicio no recrea TI ni cambia contraseñas. Si la primera habilitación falló, revisar el estado de la cuenta antes de repetir; el servicio rechaza un segundo bootstrap con cuentas existentes.
7. La credencial inicial y las de QA solo se consultan privadamente por el operador autorizado en el directorio Linux 0700, archivos 0600. No pegarlas en chat, argumentos, logs, capturas o informes. Un reset ordinario de clave se realiza mediante TI y revoca sesiones; no borrar la cuenta.
8. Repetir la verificación de custodia y el E2E con su estado previo. No redistribuir ni recrear registros para compensar una respuesta perdida; recuperar/reintentar el comando confirmado.

Las Comunicaciones manuales y operaciones de QA confirmadas son registros institucionales sintéticos auditados. Se conservan; esta reversión no autoriza eliminarlos ni reutilizar sus folios. La cobertura anterior termina su vigencia: no reescribir el origen histórico para simular una vuelta atrás.
