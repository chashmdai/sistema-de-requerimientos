# Reversión no destructiva — U4
1. Para detener únicamente las salidas de correo, establecer institucional.notificaciones.correo.modo=DESACTIVADO e institucional.notificaciones.correo.automatico=false en la configuración privada. Detener/reiniciar solo la instancia institucional con el lanzador verificado. No tocar tenant, Exchange, workers, aplicaciones públicas o servicios gubernamentales.
2. Para retirar temporalmente toda la interfaz/motor U4, establecer institucional.notificaciones.habilitadas=false y conservar el artefacto nuevo. La capacidad de sesión oculta el módulo y sus rutas quedan desactivadas; identidad, núcleo, custodia y avisos históricos conservan su funcionamiento.
3. No borrar ni modificar V1–V12, checksums, tablas de tareas/historia, fuentes procesadas, notificaciones, outbox, intentos, presupuesto o confirmaciones. No ejecutar clean/repair/DOWN, reset, recreación de volúmenes ni reutilización de folios.
4. Conservar el estado reanudable y las cuatro correlaciones aceptadas/confirmadas. AMBIGUO no vuelve a PENDIENTE por intervención automática. Reiniciar no restablece presupuesto ni autoriza reenvío. No cambiar la campaña para eludir el límite.
5. Conservar la cuenta nexbyte y sus referencias. Si se retira su acceso, hacerlo por TI mediante revocación/desactivación auditada; no eliminar ni resetear contraseñas para revertir U4.
6. application.antes-notificaciones.properties y runtime-antes-notificaciones.jar permanecen en custodia privada. No restaurar la configuración ciegamente ni copiarla a Git. Preferir flags sobre el artefacto nuevo: el código anterior presenta una incompatibilidad conocida para cuentas que combinan Distribución y Jefatura.
7. El secreto Graph permanece fuera de Git con modo 0600. No imprimirlo, incluirlo en env/argumentos, backups accesibles o informes. No se necesita rotarlo para desactivar una función; su custodia/retirada corresponde al canal privado autorizado. El original de Windows no fue modificado.
8. Para reactivar: validar Flyway con migrador separado, comprobar permisos/HTTPS y recuperar pendientes con el mismo esquema, almacén y estado. Mantener correo automático desactivado. Verificar custodia y ejecutar E2E interno; no volver a enviar la campaña completada.

Las tareas son personales de Casos y sus confirmaciones son hechos auditados. Un rollback técnico no debe convertirlas en gestiones realizadas, borrar una finalización manual ni sustituir originales ciudadanos.
